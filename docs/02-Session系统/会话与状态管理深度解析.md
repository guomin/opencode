## 核心数据模型：三层嵌套架构

OpenCode 摒弃了简单的扁平消息列表，采用了严格的树状结构来支撑复杂的流式渲染和工具调用：

*   **Session（会话）**：最顶层容器，代表一个完整的对话窗口。支持创建**子会话（Sub-Session）**来隔离复杂任务的上下文和权限。
*   **Message（消息）**：一次交互回合，分为 `User` 和 `Assistant`。
*   **Part（片段）**：状态管理的精髓。一条消息由多个 Part 组成，如 `TextPart`（文本）、`ReasoningPart`（深度思考）、`ToolPart`（工具调用，拥有 pending/running/completed 独立生命周期）。

## 状态流转与本地存储

*   **事件驱动**：`SessionProcessor` 监听大模型的流式输出，实时更新 Part 状态，并通过 `Bus` 事件总线广播增量（Delta），驱动多端 UI（Web/CLI）局部重绘。
*   **文件系统存储**：放弃了传统数据库，采用基于本地文件系统的 JSON 存储（`~/.opencode/storage/`）。按 ID 分目录存放，读写极快，天然隔离，且易于开发者直接调试。

## 优雅的上下文压缩 (Compaction)

当对话过长导致 Token 溢出时，系统会自动触发压缩机制（位于 `packages/opencode/src/session/compaction.ts`）：

*   **逻辑删除而非物理删除**：系统会找到旧的、已完成的工具调用，给它们打上 `compacted` 时间戳标记，但**绝不会从硬盘上删除原始数据**。
*   **对大模型隐藏，对用户可见**：在组装发给大模型的 Payload 时，系统会过滤掉（`filterCompacted`）这些被标记的内容以节省 Token；但在 UI 界面上，用户依然可以向上滚动查看完整的历史执行日志，保证了可回溯性和审计安全。
*   **AI 总结 (Summarize)**：如果修剪后依然超限，系统会启动一个后台的 `compaction` Agent，生成一段高度浓缩的“前情提要”，并开启一个全新的 Session，实现无缝的无限对话。

## Prompt 的动态组装

*   **System Prompt（动态拼装）**：在每次调用大模型前实时生成。结合了 Agent 专属人设、模型特性，并动态注入当前环境信息（工作目录、操作系统、Git 状态等）。
*   **User Prompt（解析展开）**：在用户提交瞬间，将富文本输入（如 `@src/main.ts`）在本地立刻读取并展开为包含文件内容的“合成片段（Synthetic Part）”，避免大模型浪费一次工具调用去读取文件。

## 工具与 MCP 的原生注入

*   **传递时机**：在每次大模型思考前（`while` 循环的起点）动态加载。
*   **统一包装**：无论是内置工具（如 `bash`）还是外部 MCP 工具，都会被统一套上一层“壳”，注入权限拦截（弹窗询问）和生命周期钩子（Plugin Hooks）。
*   **独立 Payload 传递**：**工具绝对不会被拼接成字符串塞进 Prompt 中！** 它们会被组装成一个独立的 `tools` 对象，作为平级参数传给 Vercel AI SDK，利用现代大模型原生的 Function Calling 能力，保证了极高的调用准确率。
